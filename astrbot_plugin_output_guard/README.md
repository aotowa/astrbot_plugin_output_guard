# 输出审查（astrbot_plugin_output_guard）

在每条回复真正发送给用户之前，再做一次最终审查。

审查入口是 AstrBot 的 `on_decorating_result` 钩子——它在模型/插件产出结果之后、
AstrBot 真正调用平台发送之前执行，是插件能拿到"最终要发出去的文本"的最后时机。

## 功能

- **规则审查**：关键词或正则，命中后可选择 `拦截` / `替换` / `标记可疑`，规则在 WebUI 里可视化增删。
- **AI 审查（可选）**：让模型判断内容是否适合发送，返回 JSON 结论；可配置模型、提示词、失败兜底，以及"判定不通过时拦截 / 转人工 / 自动改写"。
- **人工审查（可选）**：把消息挂起，推送到管理员会话，由管理员用指令放行或拒绝；支持超时自动丢弃/放行、拒绝时通知原会话。
- **白名单**：命中白名单正则的消息直接跳过审查。
- **运行状态**：`/审查状态` 查看规则数量、AI/人工开关、待审数量与规则错误。

## 兼容性

| 项目 | 要求 |
| --- | --- |
| AstrBot | `>= 4.29`（`metadata.yaml` 已声明，低于该版本会被阻止加载） |
| Python | 3.10+ |
| 第三方依赖 | 无 |

依赖的 4.29 API：`filter.on_decorating_result`、`event.get_result()` / `stop_event()` /
`set_extra()`、`context.send_message()`、`context.llm_generate()`、
`context.get_current_chat_provider_id()`、`MessageChain`、`ResultContentType`、
`get_astrbot_data_path()`。

## 安装

把整个 `astrbot_plugin_output_guard` 目录放到：

```
AstrBot/data/plugins/astrbot_plugin_output_guard/
├── main.py
├── reviewer.py
├── metadata.yaml
├── _conf_schema.json
├── README.md
└── tests/            # 可选，仅用于本地自测
```

然后在 WebUI 的「插件」页重载插件（或重启 AstrBot）。
安装后 WebUI 里会出现「输出审查」的配置页。

## 快速开始

1. 打开插件配置，保持「启用最终输出审查」为开。
2. 在「审查规则」里添加规则，例如：
   - 名称 `手机号`，匹配方式 `正则表达式`，匹配内容 `1[3-9]\d{9}`，动作 `替换文本`，替换为 `[手机号已隐藏]`；
   - 名称 `竞品词`，匹配方式 `关键字`，匹配内容 `某某产品`，动作 `拦截发送`；
   - 名称 `可疑内容`，匹配方式 `关键字`，匹配内容 `骂`，动作 `标记可疑`。
3. 规则改完后可以先用 `/审查测试 <一段文本>` 试跑，确认命中与替换结果。
4. 如果要用人工审查：
   1. 在希望接收审批消息的会话（建议管理员私聊）发送 `/审查会话`，复制返回的 UMO；
   2. 填到配置的「人工审查 → 接收审查通知的会话」；
   3. 把「人工审查模式」设为 `all`（全部）或 `flagged`（仅规则/AI 标记的消息）。
5. 发一条会触发规则的消息验证：被拦截的消息不会发出；转人工的消息会在管理员会话里出现 `/审查通过 <编号>` 的提示。

## 配置说明

### 顶层

| 配置 | 说明 |
| --- | --- |
| `enabled` | 总开关，关闭后插件完全不介入。 |
| `rule_scope` | `all` 审查所有输出；`llm_only` 只审查大模型回复。 |
| `rules` | 审查规则模板列表，见下。 |
| `bypass_patterns` | 白名单正则列表，消息全文命中任意一条就跳过审查。 |
| `llm_review` | AI 审查配置。 |
| `manual` | 人工审查配置。 |
| `debug` | 输出调试日志。 |

### 规则（`rules`）

| 字段 | 说明 |
| --- | --- |
| `name` | 规则名称，会出现在日志和审查通知里。 |
| `enabled` | 是否启用。 |
| `match_type` | `keyword` 子串匹配，`regex` 使用 Python `re` 语法。 |
| `pattern` | 匹配内容，支持填写多个，见下面「多个匹配内容怎么填」。 |
| `action` | `block` 拦截、`replace` 替换、`flag` 标记可疑。 |
| `replacement` | `replace` 使用的替换文本。 |
| `case_sensitive` | 是否区分大小写（仅关键字模式）。 |

规则按列表顺序执行：遇到 `block` 立即结束；`replace` 会改写后续规则看到的文本；`flag` 只累计标记。

#### 多个匹配内容怎么填

「匹配内容」现在是一个多行文本框，**换行就是分隔**，一行一个，不会被当成同一个字段。
关键字模式还可以用半角 `|` 或全角 `｜` 在一行里分隔；空格和逗号不会被当成分隔符，
所以 `bad word`、`你好，世界` 仍然是一个完整内容。

关键字规则，两种等价写法：

```text
手机号
身份证
银行卡
```

```text
手机号|身份证|银行卡
```

正则规则：**每行是一个独立的正则表达式**。正则里的 `|` 仍然表示"或"，不会被拆开：

```text
1[3-9]\d{9}
\d{17}[\dXx]
```

想在一个正则里表达"或"，照常写 `(foo|bar)` 即可。某一行正则写错时，只会跳过这一行并在
`/审查状态` 与日志里给出提示，同一条规则里其他正确的内容继续生效。
关键字模式里如果要匹配 `|` 字符本身，请改用正则模式写 `\|`。

等价 JSON 示例（换行写成 `\n`）：

```json
[
  {
    "name": "手机号",
    "enabled": true,
    "match_type": "regex",
    "pattern": "1[3-9]\\d{9}\n\\d{17}[\\dXx]",
    "action": "replace",
    "replacement": "[手机号已隐藏]",
    "case_sensitive": false
  },
  {
    "name": "竞品词",
    "enabled": true,
    "match_type": "keyword",
    "pattern": "某某产品\n竞品词",
    "action": "block",
    "replacement": "",
    "case_sensitive": false
  }
]
```

### AI 审查（`llm_review`）

| 配置 | 说明 |
| --- | --- |
| `enabled` | 开启后每条待审文本额外调用一次模型（会增加延迟和费用）。 |
| `provider_id` | 审查模型；留空使用当前会话模型。 |
| `prompt` | 提示词，`{text}` 会替换成待审查文本。要求模型只输出 JSON：`{"pass": bool, "reason": str, "rewrite": str}`。 |
| `fail_open` | 模型调用失败/返回无法解析时是否放行（默认放行）。 |
| `action_on_reject` | AI 判定不通过时：`flag` 转人工、`block` 直接拦截、`rewrite` 使用 AI 给出的改写文本。 |
| `apply_rewrite` | AI 判定通过但也给出了改写建议时，是否采用改写。 |

解析结论时的容错：支持 `pass` / `passed` / `ok` / `approved`，也支持用 `risk` 为 `high` 判定不通过；
模型把 JSON 包在 Markdown 代码块里也能解析。

### 人工审查（`manual`）

| 配置 | 说明 |
| --- | --- |
| `mode` | `disabled` 关闭；`flagged` 只挂起被标记的消息；`all` 挂起范围内全部消息。 |
| `scope` | `llm_only` 只挂起 AI 回复（推荐）；`all` 连指令回复一起挂起。 |
| `admin_umos` | 接收审查通知的会话 UMO 列表，用 `/审查会话` 获取。 |
| `timeout_seconds` | 超时时间，`0` 表示永不超时。 |
| `timeout_action` | 超时后 `drop` 丢弃或 `send` 放行。 |
| `notify_on_reject` | 拒绝时是否在原会话发一句"未通过内容审查"。 |
| `fallback_when_no_admin` | 开了人工审查但没配 `admin_umos` 时的兜底：`send` 正常发送、`drop` 丢弃。 |

## 指令

所有指令仅管理员可用，并且这些指令自身的回复不会被本插件再次审查。

| 指令 | 作用 |
| --- | --- |
| `/审查` | 查看状态摘要和待审消息列表。 |
| `/审查通过 <编号>` | 放行一条待审消息。 |
| `/审查拒绝 <编号> [原因]` | 拒绝一条待审消息。 |
| `/审查详情 <编号>` | 查看待审消息全文。 |
| `/审查全部通过` | 放行全部待审消息。 |
| `/审查全部拒绝` | 拒绝全部待审消息。 |
| `/审查测试 <文本>` | 用一段文本试跑规则，预览命中与替换结果（不调用 AI）。 |
| `/审查模式 <disabled\|flagged\|all>` | 运行时切换人工审查模式并写回配置。 |
| `/审查状态` | 查看详细配置与规则错误。 |
| `/审查会话` | 返回当前会话 UMO，用于填 `admin_umos`。 |

## 工作原理

1. AstrBot 生成结果后触发 `on_decorating_result`；
2. 插件取出 `event.get_result().chain`，拼接纯文本；
3. 依次执行白名单、规则、AI 审查；
4. 需要拦截时：清空 `result.chain` 并调用 `event.stop_event()`，消息不会进入发送阶段；
5. 需要人工审查时：复制消息链（本地附件转存到 `data/plugin_data/astrbot_plugin_output_guard/hold/<编号>/`），
   清空原结果并结束事件，然后向 `admin_umos` 推送带编号的审批消息；
6. 管理员 `/审查通过` 后，插件用 `context.send_message(umo, chain)` 把原消息补发出去；拒绝则丢弃并清理缓存。

待审消息只保存在内存中，插件重载或 AstrBot 重启后会丢失（缓存目录会在启动时清空）。

## 已知限制

- **流式输出无法拦截**：AstrBot 的流式内容在生成时直接逐段发送，不经过 `on_decorating_result` 的完整消息链；
  插件在流式结束时只会记录一次警告并跳过。需要对每条回复完整审查时，请在 AstrBot 中关闭流式输出。
- **只覆盖消息事件管线**：其他插件通过 `context.send_message()` 直接推送的主动消息不经过本插件。
- **审查时机早于 AstrBot 的后处理**：回复前缀、分段回复、TTS、文转图都在本钩子之后执行，
  所以最终呈现可能和审查时的文本略有差异（例如长文本被转成图片）。人工放行的消息是"原样补发"，
  不会再经过回复前缀、分段、TTS、文转图等后处理，附件也以转存后的本地文件发送。
- **附件转存是尽力而为**：无法深拷贝或复制失败时，放行后可能丢失附件。
- **`manual.scope = all`** 会把指令回复、权限不足提示等也挂起，体验较重，建议默认的 `llm_only`。
- 人工审查会增加回复延迟；对方在等待期间看不到任何内容，属预期行为。
- 被拒绝的消息已经写入 AstrBot 的对话历史（模型生成时就已入库），拒绝只影响"是否发出去"，
  不会回滚上下文；后续对话里模型仍可能记得这段内容。

## 自定义

- `metadata.yaml` 里的 `author`、`repo` 请改成你自己的信息。
- 需要增加新的规则动作（例如"转成图片再发"）时，可以在 `main.py` 的 `_review` / `_suppress` 之间扩展。
